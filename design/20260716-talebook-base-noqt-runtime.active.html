Final architecture note · talebook-base

无 Qt 的 Calibre，保留 Talebook 真正需要的部分

这份文档以本地 master 为基线，描述当前分支的最终实现：在 Debian 13 系统 Python 上裁剪 Calibre，只发布 ebook-convert 与 calibredb，用 Pillow、Poppler 与 WeasyPrint 替换转换链上的 Qt 职责。

01 / Summary

结论摘要

这里没有“把完整 Calibre 的 Qt import 隐藏起来”。最终方案是把产品边界缩到 Talebook 的服务器端用例，再从源码、Python 模块、Debian 包和 ELF 动态库四个层面共同收口。

核心判断 Talebook 不需要 Calibre GUI、设备管理、内容服务器和 Qt WebEngine。它需要的是电子书格式转换、书库元数据/封面操作，以及 PDF 输入输出。围绕这三项能力建立白名单，比携带完整 Calibre 后再尝试“禁用 GUI”更可靠。

04 / Build

五阶段构建：提取，不安装整包

最终镜像基于 debian:13-slim，直接使用 Debian 管理的 Python 3.13。Calibre、WeasyPrint 与 Poppler 的 Debian 包在构建阶段只下载并解包；Qt/PyQt 包在进入文件树前就被过滤。

为什么不是私有 Python 运行时

容器使用 /usr/bin/python3 和 Debian 的标准 dist-packages。Calibre 源码直接覆盖到 /usr/lib/calibre，Python 依赖沿系统路径加载；没有 PYTHONHOME，也没有另一套 Python 根目录。这样 Talebook 后续的 pip install -r 仍然落在同一个解释器生态中。

为什么仍需提取 .so

Python 源码只是依赖图的一部分。ICU、Pango、Cairo、FreeType、Poppler 辅助程序和 Calibre 原生扩展都需要动态库。构建脚本从 Debian 包展开文件，再从保留的 ELF 起点递归解析 DT_NEEDED，只复制闭包内的库；随后与最终 Debian 系统层按字节去重。

05 / No Qt

Qt 是怎样被真正移除的

移除 Qt 不是一条 patch，而是五道互相校验的边界。

  1. 能力删除：GUI、设备、内容服务器、抓取器等目录不进入 standalone 源码包。
  2. 插件白名单：只注册目标输入/输出/元数据插件与 14 个必要原生扩展，避免模块自动发现把 GUI 图重新拉回。
  3. 职责替换：图像缩放、编码、封面处理走 Pillow；PDF 输入走 Poppler；PDF 输出走 WeasyPrint。
  4. 兼容分流：img_shim.py 仅在 standalone 环境切换实现，完整 Calibre 的非 standalone 路径仍可使用原逻辑。
  5. 成品负向断言：smoke 同时检查 PyQt import 失败、Qt 文件不存在、ELF 不链接 Qt、动态依赖无缺失。

图像兼容层

calibre.utils.standalone_img 实现转换所需的 Pillow 操作；calibre.utils.img_shim 根据 CALIBRE_STANDALONE_CONVERTER 选择 Pillow 或原实现。Talebook 既有代码调用的 calibre.utils.magick.draw.thumbnail() 在 standalone 下也被导向同一后端。构建阶段还覆盖 Debian 已安装的 calibre.utils.img，因此 calibredb 的封面与元数据路径不会意外落回 Qt。

原生扩展白名单

运行时只保留：cPalmdoc、fast_css_transform、fast_html_entities、freetype、html_as_json、hyphen、icu、matcher、podofo、speedup、sqlite_custom、sqlite_extension、uchardet、unicode_names。

06 / Routing

两个公开命令，一条 PDF 内部分流

/usr/bin/ebook-convert 进入同一个 Python router。router 先建立共享运行环境，再读取目标文件扩展名：PDF 进入内部 WeasyPrint 后端；其他受支持格式进入 Calibre standalone 转换器。PDF 是 ebook-convert 的一种输出行为，不是第二个产品入口。

PDF 的数据路径

输入格式仍由 Calibre 插件解析，转换成统一 OEB 表示。内部 PDF 后端把 OEB 合并为可打印 HTML，保留 CSS、图片、字体与章节结构，再交给 WeasyPrint/Pango/Cairo 生成 PDF。这个边界保留了 Calibre 擅长的电子书语义转换，同时避开 Qt WebEngine。

参数兼容

router 接受 Talebook 已使用的 Calibre PDF 参数，将纸张和边距映射为内部 WeasyPrint 参数；与 PDF 后端无关、但常见于既有调用的选项会被有选择地忽略或透传。非 PDF 输出不经过该翻译层。

10 / Constraints

约束与最终结论

明确约束

  • 该镜像是 Talebook 的 Calibre 能力切片，不承诺完整 Calibre 命令、插件或 GUI 兼容性。
  • 新增输入/输出插件必须同时审计 Python import、资源文件、原生扩展和 ELF 闭包，不能只把模块名加入白名单。
  • PDF 版式以 WeasyPrint 的 HTML/CSS 打印模型为准，不追求与 Qt WebEngine 像素级一致。
  • 升级 Debian、Calibre 或 Python 后，必须重新执行双架构镜像 smoke 和 Talebook 集成测试。
  • 发布流程不得合并或改写 master；本设计只比较基线，不包含分支合并动作。
Final model 最终镜像不是“安装 Calibre 后删除 Qt”，而是“从 Talebook 需要的命令出发，构造 Calibre 能力与 ELF 依赖的双白名单”。源码适配让转换路径不再需要 Qt；Debian 解包、动态依赖闭包和负向 smoke 则保证成品物理上也没有 Qt。
